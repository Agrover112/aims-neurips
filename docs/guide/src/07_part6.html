27The model ladder: what each rung actually tests

Every added component must answer a question the previous rung could not. If it cannot beat the simpler control, it is not a contribution.

RungWhat it addsQuestion it answers
Constant 0.5nothingIs the model better than admitting ignorance? (Brier 0.25)
Beta-Binomialone online rateCan a conjugate update with no item content beat the constant?
1PL / 2PLper-item difficulty (± discrimination)Is there item structure worth modeling?
Amortized IRT\(f_\phi(x_j)\mapsto(a_j,b_j)\)Can content predict difficulty for unseen items?
Online-AIRTMAP \(\theta\) from acquired labelsIs a scalar Bayesian update enough?
CNP-AIRTdeterministic context encoder + correctionDoes learned global conditioning beat the analytic update?
NP-AIRTglobal latent \(z\)Does a stochastic task state add anything?
ANP-AIRTtarget-specific attention \(r^*\)Does item-to-item relevance help beyond a global summary?
Stacked ANPself-attention over contextDo context–context interactions help?
RAA-IRTexplicit relational featuresIs a gain genuinely relational, or just more parameters?
Shuffled relationsnegative controlDoes destroying the relation structure remove the gain?

The ladder is cumulative for a reason. If ANP-AIRT beats CNP-AIRT but NP-AIRT does not, the gain is attention, not the latent. If RAA-IRT beats ANP-AIRT but the shuffled-relation control does too, the gain is capacity, not relations.

Intuition

A ladder is a sequence of controlled comparisons, not a wish list. Each rung isolates one degree of freedom: item content, then subject adaptation, then a global latent, then target-specific attention. If you add two rungs at once and the score improves, you have learned that something helped — which is not a scientific claim.

Solved in 60 seconds

Model A ALC 0.224, Model B ALC 0.219, difference 0.005. Seed spread across three seeds: \(\pm0.006\).

Paired per-task differences: mean \(-0.005\), \(\mathrm{SE}=0.004\). A 95% interval is roughly \([-0.013,0.003]\) — it crosses zero.

Decision: do not claim B is better. Either run more seeds/tasks or report the comparison as inconclusive. A 0.005 gain with 0.006 noise is not a result.

In this repo

The named ladder is Online-AIRT → CNP-AIRT → NP-AIRT → ANP-AIRT → stacked ANP → per-item latent correction → hybrid anchor. The negative controls are a correction-free CNP item head, a latent with \(d_z=1\), shuffled acquisition orders, and shuffled relations. They are part of the argument, not an appendix.

28Ablations that survive review

An ablation is an experiment, not a victory lap. Freeze everything you are not testing, change one thing, and decide the rule before you see the numbers.

The repo’s binding protocol is a good template:

  • Fixed task grid. 104 validation tasks, with eligible subject–benchmark pairs defined in advance.
  • Frozen acquisition orders. Ten fixed candidate streams, one seed for the build, so seeds cannot disagree on the labels.
  • Nested budgets. The budget-3 context contains the budget-1 label, and so on.
  • Out-of-fold calibration. Five folds; calibrator parameters for a task never see that task’s outcomes.
  • One test read. The test fold is opened once, for the selected model and the baseline, after selection is complete.

Report paired per-task differences, not just two means. Report every seed, not the best one. Report benchmark-level failures, runtime, and parameter count — a gain that costs 100× compute is a different result from a free one.

Solved in 60 seconds

Question: does attention help beyond the global summary?

Design: same AIRT base, same episodes, same budgets, same calibration folds, same seeds. Arm A replaces \(r^*\) with the mean-pooled \(r\); Arm B uses attention. Everything else is identical.

Metric: paired ALC difference per task, 10 frozen orders, report mean, 95% interval, and the fraction of tasks improved.

Decision rule (written first): claim a gain only if the interval excludes zero and the gain survives the shuffled-relation control. Otherwise report “no detectable difference”.

Trap

If each arm gets its own hyperparameter search, you are comparing tuning budgets, not architectures. Fix the budget, or tune on a nested split and report the search cost.

In this repo

docs/ablation-protocol.md is the contract; docs/uniform-audit.md checks that the code actually follows it. The audit exists because an ablation protocol that is only described, not enforced, drifts.

29Failure-mode checklist

When the offline number and the leaderboard disagree, the cause is almost always on this list.

1 · Target leakage. Do evaluation outcomes enter any fit, calibration, early stop, or order choice? Check the call graph, not just the model.

2 · Subject identity in the item path. Are subject embeddings masked from \(a_j,b_j\)? If not, “difficulty” is subject-specific.

3 · Duplicate items. Do paraphrases or repeated trials cross the train/test split? Group by item and benchmark.

4 · Non-nested budgets. Does budget 7 contain the labels from 1 and 3? If not, the curve is not a learning curve.

5 · Micro vs macro. Are you averaging items when the leaderboard averages tasks? See §11.

6 · Calibration on test. Was the calibrator fitted on the evaluation tasks? It must be fitted elsewhere.

7 · AUC-only tuning. Did you select a checkpoint by AUC and then report Brier? Ranking and scale are different.

8 · Seed cherry-picking. Is the reported seed the best of several? Report all seeds and the spread.

9 · Budget-0 mismatch. Does the model at \(B=0\) reproduce the frozen anchor? The gate should force it.

10 · Padding bugs. Are padded context slots masked in the mean, the softmax, and the loss? Check a task with \(B=1\).

11 · Dead softmax. Are attention logits saturated or NaN? Inspect weights and gradients.

12 · KL collapse. Is \(z\) ignored? Resample \(z\) and see whether predictions move.

13 · Statelessness. Does the predictor rebuild from the full labelled list each call? Workers may restart between budgets.

14 · Probability clipping. Are 0 and 1 replaced by epsilon before the log? Otherwise one confident mistake produces infinity.

15 · Benchmark shift. Is the test benchmark unlike training? Report per-benchmark failures, not one average.

Solved in 60 seconds

Offline 0.18 vs leaderboard 0.31: too large for seed noise. Check calibration first (mean 0.7 vs base 0.4 means wrong scale), then the split (duplicates, subject identity, calibration on evaluation).

Diagnosis in one line each

  • Brier 0.25, AUC 0.5: no signal. Check features and leakage.
  • AUC high, Brier bad: wrong scale. Calibrate; do not retrain.
  • ECE high, AUC fine: miscalibrated only. Temperature or anchor.
  • KL ≈ 0, rank 1: latent redundant. Use a CNP or reparameterize.
  • Validation great, test bad: leakage or benchmark shift. Check the split first.
  • Bump at B = 1: overreaction. Increase shrinkage.

Ten questions

  1. Why is 0.25 the Brier baseline? A constant 0.5 gives \((0.5)^2\) on every item.
  2. Why can AUC rise while Brier falls? AUC is rank-only; Brier also cares about scale.
  3. What does a prior do at \(B=1\)? Prevents infinite ability and shrinks the update.
  4. Why divide KL by \(N_T\)? Keeps it comparable to the per-target likelihood as targets grow.
  5. What makes a CNP permutation-invariant? Per-item encoding plus a symmetric pool.
  6. What does ANP add? A target-specific context summary via attention.
  7. Why is 3PL skipped? Guessing is not identifiable from 31 labels and has no mechanism here.
  8. Why is a paired test better? Task difficulty cancels; the comparison is more precise.
  9. Why macro-average? The leaderboard weights subject–benchmark tasks equally.
  10. Why freeze the acquisition order? To separate predictor quality from label-stream luck.
The one sentence

Predict a probability for every hidden outcome, use content for the cold start, use a few labels to update a low-dimensional state, and never let the evaluation outcomes touch the fit.

A last word

You do not need to hold all of this in your head. Hold the one sentence: a subject’s ability, compared with an item’s difficulty, squashed into a probability — with the ability updated from a few labels and the difficulty predicted from content. Everything else in this guide is a detail hanging off that sentence.
