# Online replay sweep: models x acquisition policies

Frozen-panel comparison on **unseen benchmarks**. Every arm sees identical
subject-benchmark tasks, an identical disjoint acquisition/evaluation split,
and identical candidate arrival orders, so a difference between two cells is a
difference in estimator or policy and nothing else.

Protocol detail lives in [`docs/benchmark-holdout-online-replay.md`](../../../docs/benchmark-holdout-online-replay.md).
This file is the results table.

## Panel

| setting | value |
|---|---|
| panel | `benchmark-holdout-online-v1-s20261018-n15-m80-cap19000` |
| validation | **82 tasks**, 3 unseen benchmarks (`ai2d_test`, `bird_sql`, `financebench`) |
| test | 45 tasks, 3 benchmarks (`algotune`, `cmmlu`, `editbench`) |
| order seeds | 3 of the 10 frozen streams |
| budgets | 0, 1, 3, 7, 15, 31 nested |
| ALC weights | .1 / .2 / .2 / .2 / .2 / .1 |
| metrics | macro-task and micro-response Brier ALC, plus ECE per budget |
| filters | `min_item_responders=15`, `min_items_per_subject=80`, `split_seed=20261018` |

**Resolution.** The per-task ALC standard deviation is ~0.069, but the
comparison is *paired*, and the measured standard deviation of a per-task
*difference* between two arms is ~0.0358. At 82 tasks that resolves a gap of
about **0.008** at two standard errors. The earlier 5-task panel resolved only
0.032, which is wider than the entire spread between arms, so nothing could be
ranked on it.

## Arms

Six models x five policies = 30 arms. All models use the `bge_m3_long`
embedding arm (BAAI/bge-m3, cls pooling, 8192 tokens, 1024-d, content only).

| model | mode | trained on | panel clean? |
|---|---|---|---|
| beta-binomial | `beta_binomial` | nothing - closed form | yes |
| ANP w64 filtered | `anp` | benchmark holdout | yes |
| ANP w64 budgets | `anp` | benchmark holdout | yes |
| ANP w128 | `anp` | random-subject split | **no** - saw these benchmarks |
| TabPFN v2 + PCA-500 | `tabpfn` | train-only PCA | yes |
| TabFM v1.0.1 + PCA-500 | `tabfm` | train-only PCA | yes |

| policy | rule | cost |
|---|---|---|
| `random_prefix` | buy the first 31 candidates | 1x |
| `uncertainty` | buy when `abs(p - 0.5) <= 0.15` | 1x |
| `confidence_extremes` | buy when `abs(p - 0.5) >= 0.15` | 1x |
| `bernoulli_variance` | score `p(1-p)`, paced by train-probe rank | ~17x |
| `expected_brier_reduction` | score = expected squared movement of the reference predictions, paced by rank | ~33x |

`uncertainty` is a *threshold* on the predicted probability, so its label spend
depends on the predictor's calibration. `bernoulli_variance` is the same
quantity used as a *score* and paced by rank against 32 train-only probes, so
it spends the same budget whatever the calibration. They are different arms and
the first is not a renaming of the second.

Both scored policies draw their 32 reference items and 32 calibration probes
from **training** benchmarks only. A reference set built from the task's own
evaluation pool would let the policy steer toward the scored items.

## Blending, fitted after the sweep

Not an arm. Each run writes per-item probabilities to `predictions.parquet`, so
a global `w * model + (1-w) * beta` weight and a per-budget weight can both be
fitted offline at no extra compute. Fit on one half of the validation subjects
and report on the other half; an earlier per-budget blend beat beta
out-of-sample on a different panel, and the weights must not be chosen on the
episodes they are reported on.

## Four cells cannot be run

`bernoulli_variance` and `expected_brier_reduction` live in the ANP/beta
runner. `modal_tabpfn_v2_benchmark_holdout_replay.py:337` and
`modal_tabfm_benchmark_holdout_replay.py:330` validate `policy` against the
three original rules, so TabPFN and TabFM crossed with either new policy raises
`ValueError` *inside the container*, after the spend. Those four cells are
reported as `n/a`, not blank, so an empty cell always means "not yet run".

Porting the two scored policies into the tabular runners is the fix. It is
duplicated work across two files and was not done, because both tabular arms
already lose to the ANPs on the superseded panel and TabPFN is 84% fallback.

## Running it

`run_sweep.py` drives the whole grid. It skips the four impossible cells with a
printed reason, orders arms cheapest-first so a budget that runs out leaves the
informative cells done, and skips arms already on the volume so a rerun
resumes.

```bash
# plan only, spends nothing
python organized/testing/online/run_sweep.py --dry-run

# fit the tabular PCA transforms, then launch all 26 runnable arms
python organized/testing/online/run_sweep.py --profile iclrgram

# cheap policies only
python organized/testing/online/run_sweep.py --profile iclrgram --max-cost 1

# one cell
python organized/testing/online/run_sweep.py --profile iclrgram \
  --models w64-filtered --policies expected_brier_reduction

# gather finished arms into the tables above
python organized/testing/online/run_sweep.py --collect --profile iclrgram
```

Validation chooses the model and policy. The matching `--role test` cell is run
**once**, after a frozen choice, and never used for selection; the driver warns
when `--role test` is passed.

A single arm by hand, if the driver is not wanted:

```bash
PANEL=benchmark-holdout-online-v1-s20261018-n15-m80-cap19000

.venv/bin/modal run --detach --profile <workspace> \
  organized/testing/online/modal_benchmark_holdout_replay.py::main \
  --action replay --panel-name "$PANEL" --role validation \
  --prediction-mode beta_binomial --policy random_prefix \
  --max-order-seeds 3 --run-name "validation-beta-random_prefix-s3-v2"
```

`--detach` is required. These launchers call `.spawn()`, so without it the app
tears down with the local entrypoint and silently kills the spawned call.

`expected_brier_reduction` costs about 33x a threshold policy, because it
evaluates both outcomes over 32 reference items and recomputes the probe
calibration after every purchase. Budget for it separately, or exclude it with
`--max-cost 17`.
