  aude-3-haiku-20240307-v1:0

  Fill/bridge rates from docs/feature-engineering.md:25-34 (measured, 8,104
  subjects).

  A "subject" = base model + its eval settings. Same model, different harness →
  different subject.

  Item — 4 fields

  Field: item_content
  What it is: the task text
  Real example: ###Instruction: You should directly answer the question by 
  choosing ONLY the correct option... ###Question: A middle-aged  man 
  presents... (602 chars)
  ────────────────────────────────────────
  Field: item_features
  What it is: k=v;k=v metadata
  Real example: lang=en
  ────────────────────────────────────────
  Field: interactors
  What it is: other agents/tools in the eval
  Real example: "" (empty in nearly all of our corpus)
  ────────────────────────────────────────
  Field: benchmark_id
  What it is: stable anonymous alias
  Real example: benchmark_274926 (internally afrimedqa)

  Item text length: p50 251 tokens, p90 620, p99 2031, max 255,270.

  What you do NOT get

  Benchmark name, description, domain, grading criteria, asset manifests. Our
  local corpus has them ({"name": "AfriMed-QA", "description": "Released model 
  responses to multiple-choice medical questions in African healthcare 
  contexts.", "domain": "['medicine']", "response_type": "binary"}) — the 
  competition does not. benchmark_id is an opaque six-digit alias, but stable
  across submissions, so you can recognize a benchmark you've seen.

  labeled

  [[[subject_dict, item_dict], 1], [[subject_dict, item_dict], 0], ...]

  Same alias accompanies targets and acquired observations → you can match
  evidence by subject and benchmark. Label is int, 1 = correct. Empty list at
  budget 0.

  How this becomes our features

  ┌─────────┬────────────────────────────────────┬──────────────────────────┐
  │ Channel │             Built from             │     Current encoding     │
  ├─────────┼────────────────────────────────────┼──────────────────────────┤

  │         │ {item_features}"                   │ capped 256/512 tokens    │
  ├─────────┼────────────────────────────────────┼──────────────────────────┤
  │ subject │ all 8 fields newline-joined        │ MiniLM-L6-v2 → 384-d     │
  └─────────┴────────────────────────────────────┴──────────────────────────┘

  Two measured problems with that: subject_features_extra is a near-unique 
  fingerprint (7,951 distinct values out of 8,104 subjects) and dominates the
  subject text; and reasoning_effort is 100% empty but still occupies a line.

  1. lang, category, prompt_condition, task are real difficulty signal — CMMLU's

  bge_base_2pladapt is the only arm that is not pure text

  It takes frozen bge_base vectors and learns a residual MLP on top
  (modal_embedding_ablation.py:1145):

  norm = LayerNorm(768);  fc1 = Linear(768→256);  fc2 = Linear(256→768)  # fc2 
  init to ZERO
  forward(x) = x + fc2(gelu(fc1(norm(x))))

  ┌──────────────┬──────────────────────────────────────────────────────────┐
  │              │                                                          │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ Objective    │ 2PL BCE: Amortized2PL, one free ability θ per training   │
  │              │ task                                                     │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ Extra loss   │ + 1e-3 · θ², and θ -= θ.mean() after every step          │
  │              │ (identifiability)                                        │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ Optimizer    │ Adam, lr 1e-3, wd 1e-4, grad clip 1.0, 800 steps, batch  │
  │              │ 2048                                                     │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ Input        │ adapted item vector ⊕ raw subject vector (concatenated)  │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ Base encoder │ frozen                                                   │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ After        │ adapter frozen, fresh AIRT + CNP heads trained on        │
  │ fitting      │ adapted table                                            │
  └──────────────┴──────────────────────────────────────────────────────────┘

  strictly-no-worse-than-bge_base initialization. And it does end up best: R²

  bge_base's raw text embedding.

  The encoder ladder spans 384-d paraphrase-tuned → 4096-d Llama, 256 → 512

  My pick: Qwen3-Embedding-0.6B

  - 1024-d — only +33% over bge_base's 768, so the adapter and CNP heads barely
    change
  - 32K context kills the truncation question outright (our p99 is 2,031 tokens)
  - MRL → you can truncate to 768-d for free and compare apples-to-apples
    against bge_base
  - Instruction-aware → you can prompt it with "Encode this evaluation item for 
    difficulty prediction" instead of the generic similarity objective, which is
    exactly your MiniLM complaint
  - 0.6B runs on an L4; no A100 needed

  Step up to 4B only if 0.6B shows a real gain. 8B is 4096-d and reintroduces
  the dimensionality problem for ~1 MMTEB point over 4B.

  For the African-language block, there's a better option

  afrieval (948 tasks) + bridging_gap (417) + helm_afr (22) = ~1,390 train
  tasks. A paper from this month, AfriMTEB and AfriE5
  (https://arxiv.org/abs/2510.23896) (Uemura, Zhang, Adelani), built a
  59-African-language benchmark and found AfriE5 — mE5-instruct adapted via
  cross-lingual contrastive distillation — beats both Gemini-Embeddings and mE5.
